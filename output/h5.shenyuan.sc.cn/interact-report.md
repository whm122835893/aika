# 交互性实测报告

- 测试方式：Playwright iPhone 12 模拟，加载本地副本（外域请求全部拦截），真实点击 / 输入 / 导航
- 测试脚本：`tools/interact.js`、`tools/interact2.js`、`tools/interact3.js`

## 结论

**是"可交互的静态副本"**：应用完整启动，路由、点击、输入、跳转、组件渲染全部工作；
但**所有数据来自抓取时刻的快照**，涉及新查询与写操作的行为会返回空态。

## 为什么部分数据为空

原站 API 有两个特性导致**参数化查询无法回放**：

1. 端点为 md5 哈希（`api.shenyuan.sc.cn/08eec40a5e71...`），无法推断语义；
2. **请求体加密且每次带随机因子**，因此 `method + url + body` 精确匹配几乎必然 miss。

shim 已实现 URL 级回退（同 URL 返回最近一次缓存），但抓取时未访问过带参数的详情页，
该端点 URL 根本不在缓存中，故返回空态。

## 已知的操作差异

- 在本环境（桌面 Chromium 模拟）中，uni-app **响应 `click` 事件**，`touchscreen.tap` 与 touch 手势反而无效；
  真机/移动端 DevTools 下表现可能不同。
- 列表无分页加载：抓取与滚动测试均未触发新的数据请求，当前数据全部已在首屏渲染。

## 若想让详情页也有数据

需要补抓一轮带参数的详情页：用缓存中出现的真实 ID（如 42 / 22 / 153 / 1181）
访问 `#/pages/market/goodsDetails?id=<id>` 并镜像其 API 响应，
即可让这些 ID 的详情页离线显示真实数据（其余 ID 仍为空态）。
